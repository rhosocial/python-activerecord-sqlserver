Fix the ``introspect`` subcommand calling introspector methods that exist nowhere in the backend. It asked ``get_tables``/``get_views``/``get_columns``/``get_indexes``/``get_foreign_keys``/``get_triggers``/``get_constraints``/``get_procedures``/``get_functions``/``get_sequences`` -- core spells those questions ``list_tables``/``list_views``/``list_columns`` and friends -- so every type failed against a live server while the old offline fakes answered the misspelled names happily. The type-to-method mapping now lives in one place (``_steps``) and is exercised twice: the offline dispatch test checks every advertised type against the real introspector classes with no fake in the way, and a live test runs the command itself against a SQL Server. ``table`` and ``database <name>`` now render through ``get_table_info``, whose single query already fills columns, indexes and foreign keys, replacing the three separate calls plus the iteration over every table that triggers used to need.
