The extended-property family, asked by table name, plus table and column comments read from `MS_Description`; and `views NAME` on the introspect CLI, whose twelve types derive from `_TYPE_CAPABILITIES`.

Add the SQL Server catalogue questions core has no shape for, on both introspector managers with identical signatures: ``list_schemas`` (``sys.schemas`` with the owning database principal resolved by ``principal_id``, not name), ``list_extended_properties`` (``sys.extended_properties`` -- ``MS_Description`` and friends -- for one catalogue object, optionally one column, with the ``sql_variant`` value cast off the type pyodbc cannot fetch), ``list_procedures`` and ``list_functions`` (``sys.objects`` types ``P``/``PC`` and ``FN``/``IF``/``TF``/``FS``/``FT``, one builder parameterized by the code set), and ``list_sequences`` (``sys.sequences`` with every ``sql_variant`` bound cast to text and parsed back into exact ``Decimal`` values rather than floats that would round a wide sequence's bounds). Each question is built from expression nodes and rendered by the dialect, carries its family name into its cache key so two families never answer each other, and reports a schema-free family as unknown rather than returning nothing.
