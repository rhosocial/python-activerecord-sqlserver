Implemented the four migration change-point suggestion protocols on `SQLServerDialect` (and, by inheritance, `SQLServerUnicodeDialect`): column reorder answers explicit unsupported (T-SQL has no column-position clause; `ADD` only appends); table constraint changes return one `ALTER TABLE ... ADD/DROP CONSTRAINT` statement per action; table index changes use standalone `CREATE INDEX` / `DROP INDEX` statements rather than the memory-optimized-only `ALTER TABLE ... INDEX` actions; partition scheme changes return the native `CREATE PARTITION FUNCTION` -> `CREATE PARTITION SCHEME` -> `ALTER TABLE ... SWITCH` -> drop-old-scheme/function chain only on SQL Server 2008+ with the Enterprise feature set, and refuse otherwise. Opaque frozen projections that hide a constraint branch kind, a partial-index predicate or partition function boundaries are refused rather than guessed. Added offline contract tests for each protocol's tri-state value, exact SQL and documented refusals.
