## Quick Start

```python
from typing import ClassVar, Optional

from rhosocial.activerecord.base import FieldProxy
from rhosocial.activerecord.backend.impl.sqlserver.backend import SQLServerBackend
from rhosocial.activerecord.backend.impl.sqlserver.config import SQLServerConnectionConfig
from rhosocial.activerecord.backend.expression import CreateTableExpression
from rhosocial.activerecord.backend.expression.statements import (
    ColumnConstraint,
    ColumnConstraintType,
    ColumnDefinition,
)
from rhosocial.activerecord.backend.expression.types import IntegerType, VarCharType
from rhosocial.activerecord.model import ActiveRecord


class User(ActiveRecord):
    __table_name__ = "users"

    id: Optional[int] = None
    name: str
    email: str

    c: ClassVar[FieldProxy] = FieldProxy()


User.configure(
    SQLServerConnectionConfig(
        host="localhost",
        port=1433,
        database="myapp",
        username="sa",
        password="YourStrong!Passw0rd",
        driver="{ODBC Driver 17 for SQL Server}",
    ),
    SQLServerBackend,
)

dialect = User.__backend__.dialect
User.__backend__.execute(*CreateTableExpression(
    dialect,
    "users",
    columns=[
        ColumnDefinition(
            dialect, "id", IntegerType(dialect),
            constraints=[ColumnConstraint(dialect, ColumnConstraintType.PRIMARY_KEY,
                is_auto_increment=True)],
        ),
        ColumnDefinition(dialect, "name", VarCharType(dialect, 100)),
        ColumnDefinition(dialect, "email", VarCharType(dialect, 255)),
    ],
).to_sql())

user = User(name="Alice", email="alice@example.com")
user.save()
rows = User.query().where(User.c.email == "alice@example.com").all()
```

### Async

`AsyncSQLServerBackend` exposes the same API. Method names are identical; add
`await`.

```python
from rhosocial.activerecord.backend.impl.sqlserver.backend import AsyncSQLServerBackend
from rhosocial.activerecord.model import AsyncActiveRecord


class User(AsyncActiveRecord):
    ...


User.configure(config, AsyncSQLServerBackend)
rows = await User.query().where(User.c.email == "alice@example.com").all()
```

## SQL Server-Specific Features

### `OUTPUT` instead of `RETURNING`

SQL Server has no `RETURNING`; the equivalent is the `OUTPUT` clause, which
the backend emits for DML that needs to return the affected row.

### Temporal tables

Query historical state with `FOR SYSTEM_TIME`. The table must already be
declared as a system-versioned temporal table; the backend does not add the
`PERIOD FOR` clause for you.

```python
User.query().where(
    "id = ? FOR SYSTEM_TIME AS OF ?",
    (1, "2026-06-30T12:00:00"),
).all()
```

### Memory-optimized and columnstore tables

Set through the DDL expression's table options, not a model attribute:

```python
from rhosocial.activerecord.backend.impl.sqlserver.expression import (
    SQLServerCreateTableOptions,
)

CreateTableExpression(
    dialect,
    "sessions",
    columns=[...],
    table_options=SQLServerCreateTableOptions(dialect, memory_optimized=True),
)
```

## Schema Names

A `schema_name` names a schema inside the current database:

```python
class Order(ActiveRecord):
    __schema_name__ = "app"
    __tablename__ = "orders"
```

```sql
-- generated
SELECT * FROM [app].[orders]
```

Two things to keep in mind:

- **Columns take at most two parts.** `` [orders].[id] `` is correct and a
  three-part reference is a syntax error, so the schema is not repeated on the
  column. Use a three-part *name* — `database.schema.object` — when you need to
  address a different database, not to qualify a column.
- **Every user has a default schema.** `get_current_schema()` reads
  `SCHEMA_NAME()` and returns the user's default schema, `dbo` unless the user
  has one of their own. It is never `None` here, unlike PostgreSQL where the
  search path can resolve to nothing.

DDL statements take a `schema_name` of their own — views, types, indexes,
sequences, functions and triggers all accept it, defaulting to `None` for an
unqualified reference. `__schema_name__` is not consulted when DDL is built, so
a migration names the schema it means.

## Version Gates

Gates below are the versions at which this backend's own `supports_*`
switch returns `True`, probed at 10, 11, 12, 13, 14, 15, 16.
A version is the first probe at or above the real gate, so each is an
upper bound within one ladder step. Switches already `True` at the
oldest release carry no gate and are omitted.

| Min version | Capabilities that turn on |
|---|---|
| 11 (2012) | `create_sequence`, `drop_sequence`, `nonclustered_columnstore`, `offset_fetch`, `order_by_in_subquery`, `try_cast`, `try_convert`, `window_frame_clause` |
| 12 (2014) | `clustered_columnstore`, `memory_optimized_table_types`, `memory_optimized_tables` |
| 13 (2016) | `drop_type_if_exists`, `if_exists_table`, `if_exists_view`, `index_if_exists`, `json_table`, `json_type`, `system_versioning`, `temporal_tables` |
| 14 (2017) | `graph_pseudo_columns`, `graph_table_kind`, `sql_graph` |
| 15 (2019) | `edge_constraints`, `for_update_skip_locked`, `graph_path_aggregates`, `readpast`, `shortest_path` |
| 16 (2022) | `columnstore_order` |

## Known Limitations

- **No connection pooling.** `pool_size` and `pool_timeout` are accepted by
  the config class but not consumed; `connect()` opens one persistent
  connection.
- **No native arrays, and no JSON *type*.** JSON is reachable through
  functions (`JSON_VALUE`, `JSON_QUERY`) on 2016+, not through a column
  type, and `supports_json_type` gates on that.
- **Table partitioning is not implemented.** `add_partition`,
  `attach_partition`, `detach_partition`, `list_table_partitioning`,
  `range_table_partitioning`, `hash_table_partitioning` and
  `subpartitioning` are all `False` at every probed version. A model does
  not take a `__partition__` attribute.
- Also unsupported: `alter_type`, `constraint_enforced`, `create_or_replace_view`,
  `deferrable_*`, `fetch_with_ties`, `fk_match`, `returning_alias`,
  `returning_wildcard`, `set_type`, `transaction_mode`.

## Testing

Tests require a reachable SQL Server instance and must run serially.

```bash
export PYTHONPATH=src:tests
.venv3.14-ubuntu26.04/bin/pytest tests/
```

The shared contract suite lives in
[python-activerecord-testsuite](https://github.com/rhosocial/python-activerecord-testsuite):

```bash
PYTHONPATH=tests .venv3.14-ubuntu26.04/bin/pytest \
  ../python-activerecord-testsuite/src/rhosocial/activerecord/testsuite/feature/
```
